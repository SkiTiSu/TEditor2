# 视频媒体链路验证记录

验证日期：2026-10-23（Asia/Shanghai）。工作分支：`codex/ranking-video-editor`。

本记录来自真实浏览器编码、OPFS 分块写入及输出文件重新解码，未使用实时录屏或仅计算时间线长度。原始采样保存在 [VIDEO_EDITOR_LONG_RUN.json](VIDEO_EDITOR_LONG_RUN.json)。测试由短片集成测试与显式开启的长片测试组成。

| 项目 | 实测结果 |
| --- | --- |
| 浏览器 | Chrome 156.0.0.0，headless，桌面 macOS |
| 设备信息 | 浏览器平台 MacIntel；浏览器报告 15 个逻辑处理器；未采集物理 CPU 型号、GPU 或整机内存 |
| 输入素材 | 本地生成的 320×180、30 fps H.264 + AAC 短视频循环；44.1 kHz 单声道 PCM BGM 循环；色块、文字图层 |
| 时间线 | 3 条画面轨、2 条音轨；30 分钟；视频裁切/缩放；原声与 BGM 混合 |
| 输出 | 1920×1080、60 fps、H.264 + AAC、MP4 |
| 实际视频帧数 | 108,000 帧（重新读取全部视频包计数） |
| 视频 / 音频 / 总时长 | 1800.000 / 1800.000 / 1800.000 秒 |
| 导出耗时 | 394.711 秒，约 6.58 分钟；约 273.6 帧/秒 |
| 文件大小 | 79,800,515 bytes（76.10 MiB） |
| 写入策略 | fMP4，1 MiB 分块写入 OPFS；逐帧编码；每块最多 0.25 秒混合 PCM |
| 声音抽查 | 0.1 / 900.1 / 1799.6 秒处各重新解码约 0.25 秒；RMS 分别为 0.11279 / 0.11175 / 0.11081，均有实际声音 |
| 末尾画面抽查 | 1799.75 秒处重新解码画面，视频窗口颜色符合输入源 |
| JavaScript heap 采样 | 初始 10.84 MiB；峰值 90.25 MiB；末次 82.32 MiB；过程中多次垃圾回收下降 |

内存数据仅为浏览器 `performance.memory.usedJSHeapSize`，**不含浏览器原生解码器、编码器、GPU 和操作系统文件缓存**，不能据此声称浏览器总内存仅占上述数值。实现限制静态页面缓存、活动解码游标、编码队列和 PCM 分块，未将 108000 帧或 30 分钟未压缩声音保存在内存中。本次长测使用短源素材循环，验证长输出、时序、混音与写入稳定性；不代表已穷尽长源文件、所有输入编码或所有硬件性能。

短片测试验证了以下实际行为：

- 30 fps 本地 H.264/AAC 源按入点裁切，合成为 60 fps 视频；窗口变换、底图、声音和选区导出一致。1 秒输出实际为 60 帧，半秒选区实际为 30 帧。
- 44.1 kHz PCM 重采样到 48 kHz，跨片段循环、原声与 BGM 混合；音轨静音/独听、片段音量及淡入生效。
- 原生 AAC 编码器的首部延迟由双脉冲校准，使用 MP4 edit list 补偿并裁去尾部填充。两个脉冲重新解码后的峰位误差均不超过 4 个 48 kHz 采样（约 0.083 ms）；音视频时长均精确为 1 秒。
- 关联图文直接调用原有 `renderBatchPage`，修改 revision 和撤销后的分叉快照均更新画面；同轨叠化中点亮度正确。
- 同名图片和同名字体在不同图片方案中隔离。重新关联文件后缓存失效；未关联图片或实际使用的字体会阻止导出；字体别名不修改原图片文档。
- 导出取消后删除 OPFS 临时文件，原工程与媒体仍可预览；预检能定位未关联的本地文件。

## 编辑流程与导出设置回归（2026-10-24）

分支：`codex/editor-workflow-fixes`。新增的真实浏览器验收包括：

- 图片图层原生 Ctrl/Cmd+C、Ctrl/Cmd+V，跨新文档粘贴、撤销重做、文字输入框中的普通剪贴板，以及 1100 px 窗口下的工具栏布局。
- 素材库 Delete 只作用于所选素材；使用中的素材先确认影响，取消后时间线不变，确认删除所有序列中的引用后可撤销；时间线 Delete 仍只删除片段。
- 12 秒 PCM 音频生成 1200 个峰值，保留静音和 6 ms 短促峰值；时间线不同缩放级别均使用连续细腻波形。
- 模板、序列共用 1–240 fps 输入；真实模板生成 320×180 / 240 fps 序列，导出 0.25 秒 MP4，重新读取验证 60 帧、240 fps、0.25 秒。
- 导出默认 1080p / 6 Mbps；自定义码率与 VBR/CBR 模式保存到工程，重新打开后恢复。实际平均视频码率不包含音频和容器开销。

码率测试使用两秒高复杂度随机纹理视频，将相同本地源分别导出并重新统计全部视频包。原始记录见 [VIDEO_EDITOR_BITRATE_CHECK.json](VIDEO_EDITOR_BITRATE_CHECK.json)。三次输出均为 60 帧 / 2 秒，且末段画面可重新解码。

| 请求 | 实际平均视频码率 | MP4 字节数 |
| --- | --- | --- |
| 6 Mbps VBR | 17.912 Mbps | 4,480,733 |
| 40 Mbps VBR | 40.962 Mbps | 10,243,387 |
| 6 Mbps CBR | 17.912 Mbps | 4,480,733 |

这些结果证明码率设置会影响输出，但也揭示本机编码器对极复杂短片会超出目标，且可能忽略 CBR 请求。因此应用显示实际码率和明显偏差提示，**没有承诺固定文件大小、严格码率上限或 B 站免二压**。纯色/静态图文则可能远低于目标。额外比较软件编码没有改善该极端样本的码率控制，低延迟模式出现丢帧，因此生产导出保留 `latencyMode: quality`，以完整帧数为准。该诊断未改用低延迟或强制软件编码。
